---
title: 'Update agent prompt'
description: 'Persist the system prompt, first message, or both to the SDK agent’s live ElevenLabs branch.'
---

```http
PATCH /api/org/{orgSlug}/sdk-agents/{agentId}/prompt
Content-Type: application/json
```

The authorization and path parameters match [GET agent prompt](/api-reference/endpoint/get-agent-prompt). Use an authenticated same-origin administrator session. The endpoint does not accept cross-origin browser writes or visitor widget credentials.

## Request body

| Field | Required | Validation |
| --- | --- | --- |
| `systemPrompt` | At least one editable field | Non-empty string, at most 100,000 UTF-8 bytes |
| `firstMessage` | At least one editable field | String, at most 10,000 UTF-8 bytes; empty string is allowed |
| `expectedRevision` | Yes | The 64-character lowercase hexadecimal revision returned by GET |

Unknown fields and `null` prompt values are rejected. Omitted fields are preserved. The encoded request body is capped at 700,000 bytes to bound escaped JSON input as well as decoded text.

```ts
const current = await admin.getPrompt()
const saved = await admin.updatePrompt({
  firstMessage: 'Hi! How can I help?',
  expectedRevision: current.revision,
})
```

This example changes only the opener. Add `systemPrompt` to update both in the same provider request. Set `firstMessage: ''` to let the visitor speak first.

## Provider behavior

The server checks ownership, discovers the fully live branch, compares the revision, PATCHes the requested fields on ElevenLabs, then reads the live branch again. It verifies both prompt fields and the branch identity before returning the same response shape as GET. No new provider write is needed when both desired values already match.

Only `conversation_config.agent.prompt.prompt` and `conversation_config.agent.first_message` are eligible for this PATCH. Tool configuration, voice, model and traffic allocation are not editable through this endpoint.

Saved settings affect subsequent unpinned conversations. Per-session overrides and active conversations can retain other values. See [prompt scope](/guides/widget-sdk/agent-prompts#understand-what-future-visitors-use).

## Failure behavior

| HTTP / code | Meaning |
| --- | --- |
| `400 invalid_prompt_update` / `invalid_json` | Correct the request fields or JSON |
| `403` / `admin_required` / `origin_not_allowed` | Use authorized same-origin administrator access |
| `404 agent_not_found` | The exact SDK agent needs a server-side ownership binding |
| `409 prompt_conflict` | The editor is stale; reload before saving |
| `409 agent_traffic_conflict` / `shared_agent` | Resolve live traffic or ownership separately |
| `413 request_too_large` | Encoded body exceeds the limit |
| `415 invalid_content_type` | Send `application/json` |
| `503 provider_not_configured` | Configure the backend's provider key |
| `502 provider_update_unconfirmed` | Provider write outcome is unknown |
| `502 provider_verification_failed` | Provider accepted the write, but verification failed |
| `502 prompt_management_failed` / `provider_request_failed` | The operation could not be completed |

```json
{
  "error": "The ElevenLabs update could not be confirmed. Reload the prompt before retrying.",
  "code": "provider_update_unconfirmed",
  "providerUpdate": "unknown"
}
```

`providerUpdate`, when present, is `not_attempted`, `unknown`, or `applied`. Never infer from an HTTP failure that the old prompt remains active. Neither the SDK nor backend automatically retries a save. Revision checking detects stale edits but is not an atomic lock against concurrent provider-dashboard changes.
