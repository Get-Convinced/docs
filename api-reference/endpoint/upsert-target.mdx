---
title: 'Upsert campaign target'
openapi: 'POST /api/campaigns/{campaignSlug}/targets'
---

Save a target in an existing campaign using your server's partner key. This is a replacement upsert, not a partial update. See [API overview](/api-reference/introduction) for the public origin.

## Request body

| Field | Meaning |
| --- | --- |
| `companyName` | Required non-empty string |
| `token` | Optional identifier; derived from companyName when absent or blank, normalized and truncated to 64 characters |
| `intel` | Optional structured [account intel](/guides/campaigns/intel-schema); when valid and present, takes precedence and skips synthesis |
| `enrich` | Boolean, defaults true; without intel, controls whether the service attempts to start synthesis |
| `rawResearch` | Optional research notes |
| `links` | Optional strings; trimmed, blank/non-string entries discarded, at most 20 retained |
| `additionalContext` | Optional notes used during synthesis/research; not currently appended verbatim to the live session prompt |

The expected `enrich` type is boolean. The current parser coerces supplied values, so a string such as `"false"` does not behave like false. Send real JSON booleans.

## Partner-intel example

```bash
curl --fail-with-body "$CONVINCED_API_BASE/api/campaigns/logistics-outreach/targets" \
  -H "Authorization: Bearer $CONVINCED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "companyName":"Acme Logistics",
    "token":"acme-logistics",
    "enrich":false,
    "intel":{
      "companySummary":"A logistics company coordinating last-mile deliveries.",
      "painPoints":["Dispatchers spend too much time updating delivery plans."]
    }
  }'
```

## Mode selection

| Inputs | Result |
| --- | --- |
| Valid intel, any enrich setting | Store normalized intel; `skipped`; no synthesis |
| No intel, enrich true or omitted | Store `pending`; attempt to start enrichment |
| No intel, enrich false | Store `pending`; no enrichment trigger |

Sending both `intel` and `rawResearch` is accepted: intel wins. Sending neither with `enrich: false` is also accepted but leaves an unready row. Prefer explicit partner-intel or [auto-enrich](/guides/campaigns/auto-enrich) inputs rather than relying on these edge cases.

```json
  "target": {
    "id": "22222222-2222-4222-8222-222222222222",

    "companyName": "Acme Logistics",
    "token": "acme-logistics",
    "enrichedAt": "2026-09-14T10:00:00.000Z",
    "enrichmentStatus": "skipped",
    "createdAt": "2026-09-14T10:00:00.000Z",
    "updatedAt": "2026-09-14T10:00:00.000Z"
  },
  "targetId": "22222222-2222-4222-8222-222222222222",
  "widgetToken": "acme-logistics",
  "widgetParam": "c",
  "widgetQuery": "?c=acme-logistics"

```

For auto-enrichment, the initial response uses `enrichedAt: null` and `enrichmentStatus: "pending"`. Neither upsert mode includes `widgetReady`; read [GET target status](/api-reference/endpoint/get-target) before sending visitors.

Unmatched submitted case-study names are dropped and reported in `warnings.droppedCaseStudies`. See [case-study validation](/guides/campaigns/partner-intel#case-study-validation).

## Token reuse and replacement

Tokens are unique per organization. The same token updates the same target, including moving it into the campaign named by this request. Reusing a token in another campaign does not produce `409`.

The upsert replaces company name, research, additional context, links, intel, campaign assignment, and enrichment state; omitted replaceable fields are cleared. Target ID and creation time remain. It also clears stored crawled links. Use distinct tokens for distinct records and serialize writes: an existing enrichment worker is not canceled by a replacement and can race with it.

## Errors

| Status | Example or meaning |
| --- | --- |
| `400` | `companyName is required`, `intel.companySummary is required`, or `intel.painPoints must be a non-empty array of strings` |
| `401` / `403` | Credential or campaign-scope problem |
| `404` | `Campaign not found` |
| `413` | Body larger than 1 MiB |
| `429` | Shared partner-key limit reached |
| `500` | Operation failed |

Error text is explanatory, not a stable error-code contract. The full [enrichment lifecycle](/api-reference/introduction#the-enrichment-lifecycle) describes what to do after a successful write.
