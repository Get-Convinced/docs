For a website integration, share the [SDK overview](/guides/widget-sdk/overview) with your development team. This reference explains the service APIs behind optional account and knowledge integrations.

## API surfaces

| Surface | Production origin | Authentication |
| --- | --- | --- |
| Campaign API | `https://convinced-kb-mcp-production.up.railway.app` | Partner key on your backend |
| Knowledge REST API, `POST /api/tool` | The same public Knowledge service origin | Partner key on your backend |
| Browser widget runtime | `https://app.getconvinced.ai` | Public widget configuration and the deployed runtime's session flow |
| SDK agent prompt management | `https://app.getconvinced.ai`, or an approved same-origin management proxy | Authenticated Convinced organization ADMIN access |

Partner keys do not authorize prompt administration. A public website cannot become an administrator by setting an agent ID or forwarding a visitor's local application login. A customer-origin proxy must authenticate and authorize an administrator server-side and expose only the bounded management path. See [prompt editor setup](/guides/widget-sdk/agent-prompts) for the supported arrangements.

## Campaign base URL

```bash
export CONVINCED_API_BASE="https://convinced-kb-mcp-production.up.railway.app"
export CONVINCED_API_KEY="<your-partner-api-key>"
```

This is a public HTTPS service; do not use a Railway internal hostname or append campaign paths to the Convinced dashboard origin.

## Authentication

Create a key in your organization's [Settings → API Keys](/guides/getting-started/api-keys), then send:

```http
Authorization: Bearer <your-partner-api-key>
```

Keep the key server-side. Campaign requests require `partner` or `internal` scope and bind access to the key's organization. A missing key returns `401` with `{ "error": "No API key provided" }`.

## Endpoints

- [Upsert campaign](/api-reference/endpoint/upsert-campaign): `POST /api/campaigns`.
- [Upsert target](/api-reference/endpoint/upsert-target): `POST /api/campaigns/{campaignSlug}/targets`.
- [Read target](/api-reference/endpoint/get-target): `GET /api/campaigns/{campaignSlug}/targets/{token}`.
- [Read saved agent prompt](/api-reference/endpoint/get-agent-prompt) and [update it](/api-reference/endpoint/update-agent-prompt): the separate ADMIN API on the app origin.

The campaign endpoints are also described in the [OpenAPI document](/api-reference/openapi.json). The manual agent-management pages document their separate authentication and origin.

## The two modes

Send structured `intel` with `enrich: false` for synchronous partner intel. Send research notes and `enrich: true` for asynchronous synthesis. Valid supplied intel takes precedence over research and skips synthesis, including when `enrich` is omitted or true.

Without intel, `enrich: false` can store a pending row without starting a worker. Auto-enrichment without useful research, context, or links can remain unready or fail. Validate your intended mode before sending.

## The enrichment lifecycle

| State | Meaning |
| --- | --- |
| `pending` | Stored and not completed; worker startup is not guaranteed by this status |
| `running` | Enrichment is in progress |
| `done` | Enrichment completed |
| `failed` | Enrichment failed; inspect `enrichmentError` |
| `skipped` | Partner intel was accepted without synthesis |

GET returns `widgetReady: true` when the campaign is active, intel is present, and status is `done` or `skipped`. Use this as the readiness gate for both modes. Upsert responses do not include `widgetReady`.

## Write semantics

Campaign upserts match `(organization, normalized slug)`. They update the name and a non-empty description; omitting or blanking the description preserves the old description.

Target upserts match `(organization, normalized token)`, replace the target's data and campaign assignment, and reset enrichment state. Reusing a token under another campaign moves the existing target; it does not return `409`. Omitted replaceable fields are cleared. Keep tokens stable and serialize writes per target.

A repeated upsert can trigger enrichment again. It does not cancel a running worker or provide an idempotency guarantee for the external work. Use GET to check progress.

## Errors and limits

Campaign errors contain an `error` string. Do not parse its wording as a stable machine-readable code.

| Status | Meaning |
| --- | --- |
| `400` | Invalid request or required field |
| `401` | Missing, invalid, expired, or disabled key |
| `403` | Key scope is not allowed to manage campaigns |
| `404` | Campaign or target not found in the key's organization |
| `413` | Encoded JSON body exceeds 1 MiB |
| `429` | Shared per-key quota exceeded |
| `500` | Service operation failed |

The default quota is 2,000 requests/hour per service process, shared with Knowledge REST calls. Campaign `429` responses currently omit `retryAfterSeconds`; use bounded backoff. Poll at five-second intervals with a finite timeout, and coordinate large batches with Convinced.

## Response naming

Campaign objects currently return `created_at` and `updated_at` in snake_case. Target objects return timestamps such as `createdAt`, `updatedAt`, and `enrichedAt` in camelCase. Use each endpoint's documented shape.
