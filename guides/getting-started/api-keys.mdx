A Convinced partner key authenticates server-side requests to the [Campaign API](/api-reference/introduction) and [Knowledge REST API](/guides/mcp/setup). The key belongs to one organization.

It does not authorize [SDK prompt editing](/guides/widget-sdk/agent-prompts), which requires a Convinced organization ADMIN session. It is also not an ElevenLabs key, a browser widget token, or an OAuth MCP access token.

## Generate a key

1. Sign in to [Convinced](https://app.getconvinced.ai) as a member of the organization.
2. Open `https://app.getconvinced.ai/org/<your-org-slug>/settings/api-keys`.
3. Create an API key with a descriptive name and an expiry appropriate to your integration.
4. Copy the plaintext key when shown and store it as a server-side secret. It cannot be retrieved later.

New dashboard keys have `partner` scope and a default quota of 2,000 requests/hour. The dashboard does not offer a way to grant yourself internal scope.

## Key format

```text
ck_live_<48 hexadecimal characters>
```

The random body contains 24 bytes. Convinced stores a SHA-256 hash and displays a prefix/suffix for identification. Treat the full key as secret: never put it in a browser bundle, repository, documentation example, or website WebMCP tool.

## Expiry presets

Choose an expiry in the dashboard or leave it without expiry if your integration requires that. Use a finite lifetime and a rotation reminder for long-running integrations. The API checks expiry when authenticating a request, including cached key records.

## Use the key

```bash
export CONVINCED_API_BASE="https://convinced-kb-mcp-production.up.railway.app"
export CONVINCED_API_KEY="<your-partner-api-key>"

curl --fail-with-body "$CONVINCED_API_BASE/api/tool" \
  -H "Authorization: Bearer $CONVINCED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"tool":"search_knowledge","args":{"query":"dispatch planning","limit":5},"scope":"partner"}'
```

Both REST surfaces accept `Authorization: Bearer <key>`. The legacy `x-api-key: <key>` header is also accepted. The stored key selects its organization and scope; request fields cannot grant additional access.

The legacy `/sse` and `/messages` MCP routes are retired. Do not use a partner key in an old SSE configuration. See [Knowledge API and MCP](/guides/mcp/overview).

## Revoke a key

Revoke the key from the same API keys page. Revocation disables the stored key permanently; create a replacement to restore an integration.

The Knowledge service caches key records for up to five minutes per process. A revoked key can remain usable until its cached entry expires. Allow for that delay when verifying revocation.

For a planned rotation: create a new key, update your backend, verify successful requests with the new key, and then revoke the old key.

## Observability

Authentication updates the key's last-used timestamp on a best-effort basis. The dashboard displays usage fields, but current Campaign/Knowledge handlers do not guarantee complete per-key request counts or detailed activity rows for every call. Maintain your own request status, latency, and retry logs without storing plaintext keys or sensitive payloads.

## Rate limits

The default quota is 2,000 requests/hour per key, shared by Campaign and Knowledge REST calls. Enforcement uses an in-memory bucket per service process, so the limit is not a globally synchronized billing counter.

Knowledge REST `429` responses include `retryAfterSeconds`:

```json
{
  "error": "Rate limit exceeded for scope \"partner\". Try again in 487s.",
  "retryAfterSeconds": 487
}
```

Campaign `429` responses currently contain only an `error` string, without `retryAfterSeconds`. Use bounded backoff for that surface and contact Convinced before bulk ingestion. Do not automatically repeat a campaign write while enrichment is running.

## Scopes and the partner tier

`partner` grants the REST tools described in [Knowledge tools](/guides/mcp/tools) and Campaign API access. It does not grant SDK management access or general knowledge-base mutation access. Tool filtering and result shape vary; review content before showing it publicly.

## Common errors

| Status | Meaning |
| --- | --- |
| `401 No API key provided` | Missing credential |
| `401 Invalid API key` | No matching key |
| `401 API key is disabled` | Revoked key after cache expiry |
| `401 API key has expired` | Expiry reached |
| `403` | The key does not have access to the requested tool or organization |
| `429` | Per-process key quota exceeded |
