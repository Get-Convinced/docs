title: 'Partner-intel mode'
description: 'Save structured account facts without running automatic enrichment.'

---

Use partner-intel mode when your team already has structured account context. The API validates and normalizes the supported fields, stores the result, and returns `enrichmentStatus: "skipped"`. It does not run the auto-enrichment pipeline. Subsequent agent conversations and other generated UI content can still use models.

## Create the campaign

Set the public API origin and key on your server as shown in [Campaign quickstart](/quickstart), then create a campaign with `POST /api/campaigns`. Save the returned slug.

## Save structured intel

```bash
curl --fail-with-body "$CONVINCED_API_BASE/api/campaigns/logistics-outreach/targets" \
  -H "Authorization: Bearer $CONVINCED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "companyName":"Acme Logistics",
    "token":"acme-logistics",
    "enrich":false,
    "intel":{
      "companySummary":"A logistics company coordinating last-mile deliveries.",
      "industry":"Logistics",
      "champion":{"name":"Priya Rao","role":"VP Operations"},
      "painPoints":["Dispatchers spend too much time updating delivery plans."],
      "currentStack":["SAP TMS"]
    }
  }'
```

Use only facts your team can verify. See [Intel schema](/guides/campaigns/intel-schema) for fields and normalization.

The response includes the target's ID, normalized token, timestamps, and `enrichmentStatus: "skipped"`, plus `widgetToken`, `widgetParam: "c"`, and `widgetQuery`. Read [GET target status](/api-reference/endpoint/get-target) to check `widgetReady`; a successful upsert alone does not establish that the campaign is active.

## Case-study validation

For submitted `intel.relevantCaseStudies`, the API matches customer names case-insensitively against the organization's case studies marked referenceable and servable. Unknown names are removed. The response reports dropped names:

```json
{
  "warnings": {
    "droppedCaseStudies": ["Unknown customer"],
    "reason": "Names not found in this org's referenceable case studies"
  }
}
```

This is a response fragment. Other target and widget fields are also returned. If all names are removed, the stored intel omits `relevantCaseStudies`. Confirm approved customer names in your dashboard, then re-submit the full corrected target.

## Re-running an upsert

The conflict key is `(organizationId, token)`. Repeating it preserves the target ID and creation time, but replaces its company name, campaign assignment, intel, research, links, and additional context. Omitted replaceable fields become empty or null; this is not a partial PATCH.

The write also clears crawled-link results and resets enrichment state. Reusing the token under a different campaign moves the existing target there. If a worker is already running, a re-POST does not cancel it and its eventual result can race with your replacement. Serialize writes for each token.

## Additional context

`additionalContext` is stored with the record and used by auto-enrichment when that pipeline runs. It is not currently appended verbatim to live session prompts. Do not use it to set persistent agent instructions; use [prompt administration](/guides/widget-sdk/agent-prompts).

## Send visitors to the widget

After GET returns `widgetReady: true`, append the returned `widgetQuery` to your landing page or use a hosted URL:

```text
https://app.getconvinced.ai/widget/v2/<your-org-slug>?c=acme-logistics
```

See [Widget embedding](/guides/campaigns/widget-embedding). For SDK integrations, also apply the campaign session context as described in [Campaign sessions in the SDK](/guides/widget-sdk/campaigns).
