`intel` is a structured account record. Submit it to [the target endpoint](/api-reference/endpoint/upsert-target) to skip auto-enrichment. The API copies recognized fields into a new object; it does not preserve arbitrary JSON unchanged.

## Schema validation summary

This table describes **submitted partner intel**. Auto-enrichment has a separate output validator, described below.

| Field | Expected type | Submitted-intel behavior |
| --- | --- | --- |
| `companySummary` | `string` | Required; non-empty after trimming |
| `painPoints` | `string[]` | Required; at least one non-empty string remains after normalization |
| `industry` | `string` | Optional; trimmed, empty or non-string values dropped |
| `size` | `string` | Optional; trimmed, empty or non-string values dropped |
| `champion` | `{ name: string; role: string; context?: string }` | Optional; the entire object is omitted unless both name and role are non-empty strings |
| `currentStack` | `string[]` | Optional; non-string and blank entries removed |
| `recentSignals` | `string[]` | Optional; non-string and blank entries removed |
| `competitorUsage` | `string` | Optional; trimmed, empty or non-string values dropped |
| `relevantCaseStudies` | `string[]` | Optional; normalized names matched case-insensitively against referenceable, servable case studies |

Unknown fields are ignored. Empty optional arrays are omitted. The request body is limited to 1 MiB; the table is not a strict validation guarantee for every invalid optional value, because the parser drops many invalid values rather than rejecting the request.

## Worked example

```json
{
  "companySummary": "Acme Logistics coordinates last-mile deliveries for grocery chains.",
  "industry": "Logistics",
  "size": "200–500 employees",
  "champion": {
    "name": "Priya Rao",
    "role": "VP Operations",
    "context": "Owns dispatch service levels."
  },
  "painPoints": [
    "Dispatchers spend too much time updating delivery plans.",
    "Teams cannot easily reconcile changes across systems."
  ],
  "currentStack": ["SAP TMS"],
  "recentSignals": ["Expanding delivery coverage, according to the account team."],
  "competitorUsage": "Evaluating another dispatch platform."
}
```

This is illustrative account data. Replace it with verified information about your target. Include customer names in `relevantCaseStudies` only after confirming they are approved proof points in your organization.

## How the session uses each field

The session builds company-profile context from `companySummary`, `industry`, `size`, `champion`, `currentStack`, `recentSignals`, and `competitorUsage`. Up to the first six pain points become session challenges. Relevant case-study names become suggested proof points; they do not restrict the model to an exclusive list of customers.

A champion is account context, not authenticated visitor identity. The session does not assume that the person holding the link is the named champion. Campaign personalization also does not itself set a saved first message; the voice or chat integration must apply the session context correctly. See [Campaign sessions in the SDK](/guides/widget-sdk/campaigns).

These fields guide the agent. They do not guarantee a specific opener, complete grounding, or the absence of model errors. Validate representative conversations.

## Case-study validation

For directly submitted intel, unmatched names are removed and returned as `warnings.droppedCaseStudies`. If all names are removed, the stored intel omits the field. See [Partner-intel case-study validation](/guides/campaigns/partner-intel#case-study-validation).

Auto-enrichment uses a separate validator: it requires a summary, normalizes optional fields, and caps pain points at six, but can accept an empty pain-point list. Referenceable names are supplied to the synthesis prompt; the output is not subsequently checked against the database using the partner-intel filter. Review generated proof suggestions before launch.

## Additional context

`additionalContext` is a sibling of `intel` in a target upsert, not an intel field. It is stored and used during auto-enrichment, but is not currently appended verbatim to the live session prompt. Use the supported account fields for facts and [agent prompt administration](/guides/widget-sdk/agent-prompts) for saved agent instructions.
