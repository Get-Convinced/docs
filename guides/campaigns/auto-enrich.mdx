Auto-enrich creates structured account intel from research notes, optional links, and additional context. It uses external research, knowledge retrieval, link crawling, and model synthesis. Completion time varies; the API does not promise a 30–90 second service level.

## Step 1: Save a target

Create the campaign first and configure the server-side API origin and key using [Campaign quickstart](/quickstart).

```bash
curl --fail-with-body "$CONVINCED_API_BASE/api/campaigns/logistics-outreach/targets" \
  -H "Authorization: Bearer $CONVINCED_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "companyName":"Acme Logistics",
    "token":"acme-logistics",
    "enrich":true,
    "rawResearch":"Dispatchers manually update delivery plans. The operations team wants to reduce replanning time.",
    "additionalContext":"Focus the research on last-mile dispatch operations.",
    "links":["https://your-account-research-page.example"]
  }'
```

Replace the example link with a real relevant public page, or omit `links`. Send at least one useful source in `rawResearch`, `additionalContext`, or `links`. Empty sources are not guaranteed to produce a synchronous validation error: the target can be stored but never become ready.

The response contains `target.enrichmentStatus: "pending"` and the widget token. The API attempts to start enrichment after responding; `pending` alone is not confirmation that the worker has started. Supplying valid `intel` skips synthesis, regardless of `enrich`.

## Step 2: Poll until ready

Call GET every five seconds with a bounded overall timeout. Check `widgetReady`, not just `done`.

```ts
async function waitForTarget(campaignSlug: string, token: string) {
  const base = process.env.CONVINCED_API_BASE
  const key = process.env.CONVINCED_API_KEY
  if (!base || !key) throw new Error('Configure Campaign API credentials')
  const deadline = Date.now() + 5 * 60_000

  while (Date.now() < deadline) {
    const response = await fetch(
      `${base}/api/campaigns/${encodeURIComponent(campaignSlug)}/targets/${encodeURIComponent(token)}`,
      { headers: { Authorization: `Bearer ${key}` }, signal: AbortSignal.timeout(10_000) },
    )
    if (!response.ok) throw new Error(`Campaign API ${response.status}`)
    const body = await response.json()
    if (body.target.widgetReady) return body
    if (body.target.enrichmentStatus === 'failed') {
      throw new Error(body.target.enrichmentError ?? 'Enrichment failed')
    }
    await new Promise(resolve => setTimeout(resolve, 5_000))
  }
  throw new Error('Timed out waiting; inspect the target before retrying a write')
}
```

This helper runs on your server. It makes no automatic write retries. A timeout reports what the client stopped waiting for; it does not cancel enrichment.

## Inputs and how they are used

| Input | Behavior |
| --- | --- |
| `rawResearch` | Notes included in the synthesis prompt |
| `links` | Trimmed strings, at most 20 retained by the API; the crawler can process a smaller bounded subset |
| `additionalContext` | Included in synthesis and used to guide external research |

Keep notes concise and distinguish facts from hypotheses. The encoded request body must fit within 1 MiB. URL strings are not proof that a page is reachable or crawlable; inspect the resulting account context.

`additionalContext` is not currently appended verbatim to the live agent prompt. Stored crawled excerpts can enter campaign session context, with excerpts shortened for runtime use. Neither mechanism edits the saved ElevenLabs instructions or opener.

## Output validation

Synthesis must produce a non-empty company summary. It normalizes optional fields and limits synthesized pain points to six. Unlike submitted partner intel, the synthesis validator can accept an empty pain-point list.

The synthesis prompt is given referenceable customer names, but the current output validator does not perform the same database name filtering as the partner-intel endpoint. Review generated intel before sending a campaign to real visitors.

## Failures and retries

The worker sets `running`, then `done` or `failed`. Failures can include missing source material or synthesis errors. `enrichmentError` is limited to 500 characters. Web-search and knowledge-lookup failures can be nonfatal, allowing synthesis to proceed with remaining inputs.

A target that remains pending or running needs investigation. Do not repeatedly POST to check progress. Re-POST replaces fields and resets visible state, but does not cancel an existing worker; concurrent runs can overwrite each other. After confirming the old attempt has ended, correct the source data and POST the full desired record with the same token.

## Cost and rate considerations

Auto-enrichment uses model/provider calls; partner-intel avoids that enrichment work. Both modes still share the Campaign/Knowledge key's request limit (2,000 requests/hour per process by default). GET polling also consumes requests. Coordinate bulk jobs with Convinced and bound concurrency.
