These names are for `POST /api/tool` on the [Knowledge service](/guides/mcp/setup). They are not website WebMCP tools or internal MCP aliases. Keep your partner key on your server.

## Calling convention

```json
{
  "tool": "get_customer_story",
  "args": { "customer": "<a customer in your knowledge base>" },
  "scope": "partner"
}
```

Most handlers return JSON objects, but catalog and industry-proof handlers return Markdown. Use [the setup example](/guides/mcp/setup#server-side-javascript) to read either format. Output depends on the organization's knowledge; there is no single shared response schema. The argument types below describe the expected inputs, not a promise that every handler performs strict runtime validation.

## Products and integrations

| REST tool | Arguments | Result |
| --- | --- | --- |
| `get_product_overview` | `product: string` | Product context; an unresolved name can return a combined overview |
| `get_module_features` | `module?: string`, `product?: string`; supply one | Feature and module context |
| `get_product_catalog` | `product?: string` | Markdown product/module/feature catalog |
| `get_integration_details` | `integration?: string` | Matching integration details, or available integration names when omitted |

## Customer proof and pain points

| REST tool | Arguments | Result |
| --- | --- | --- |
| `list_customers` | `industry?: string` | Customer list with scope/disclosure processing |
| `get_customer_story` | `customer: string` | Customer story or available fallback evidence |
| `resolve_pain` | `query: string`, `industry?: string` | Pain, capability, and supporting evidence matches |
| `list_pain_points_by_industry` | `industry?: string` | Pain points; an unrecognized filter can broaden the result to all industries |
| `get_industry_proof` | `industry: string` | Markdown proof bundle or no-match explanation |
| `get_objection_response` | `objection?: string`, `category?: string`; supply one | Matching objections and response frameworks |

## Search, slides, and competitors

| REST tool | Arguments | Result |
| --- | --- | --- |
| `search_knowledge` | `query: string`, `limit?: number` (default 15) | Knowledge matches; use a small positive limit such as 5 |
| `show_relevant_slide` | `query: string`, `limit?: number` (default 3) | Slide action or `action: "skip"` when no relevant slide is found |
| `get_knowledge_stats` | `{}` | Counts and coverage information |
| `list_competitors` | `{}` | Competitor list; the current handler does not apply an industry filter |
| `get_competitor_comparison` | `competitor_name: string`, `product_name?: string` | Comparison evidence or `noData: true` |
| `get_competitor_battlecard` | `competitor_name: string` | Composite comparison and knowledge context |
| `research_company` | `company?: string`, `email?: string`; supply one | Knowledge lookup, with external research fallback when no match is found |
| `research_web` | `company?: string`, `query?: string`, `topic?: string`; supply one | Knowledge lookup, with external research fallback |

External research tools can call a model/provider and take longer than a simple knowledge lookup. Review results for relevance and evidence before using them in a public response.

## Names and current limitations

- Use `get_product_overview`, not `get_product`; `get_customer_story`, not `get_case_study`; and `get_competitor_comparison`, not `get_competitor` on the REST endpoint. Internal registry names are not automatically REST aliases.
- `get_roi_calculator` is not a registered REST handler and returns an unknown-tool error.
- `get_buyer_question_context` is explicitly internal-only on this endpoint.
- Mutation and most prospect tools are outside the normal partner integration. Do not infer access from an internal catalog; a stored scope and the REST dispatch mapping determine the actual result.
- The current REST mapping also admits `prep_outreach` and `search_similar_prospects` for partner keys. They are not recommended website integrations; discuss their data and disclosure behavior with Convinced before use.
- `get_industry_playbook` is present in the dispatch table, but currently combines Markdown-returning handlers using JSON parsing. Use `list_pain_points_by_industry` and `get_industry_proof` separately.
- Filtering is tool-specific. Do not assume a uniform guarantee that every nested competitor field or composite result is suitable for publication.

## Handle empty and failed results

Check HTTP status first, then inspect the returned value. Some handlers signal failure inside a `200` response with `{ "error": "..." }`; others use `message`, `noData`, or `action: "skip"`. Preserve an explicit no-result outcome rather than filling missing facts.

For an agent that operates your website, register the page's actions through [WebMCP](/guides/widget-sdk/webmcp) and keep Knowledge API calls in your backend. A page-action tool can call an authorized application API, but the partner key must never appear in its browser implementation.
