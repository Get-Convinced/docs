Use the Convinced Knowledge API when your server needs product information, customer stories, pain points, or other context from your organization's knowledge base.

## Choose the right interface

| Interface | Purpose | Authentication |
| --- | --- | --- |
| Partner Knowledge REST API, `POST /api/tool` | Call a knowledge tool from your backend | Organization-bound partner API key |
| Campaign REST API, `/api/campaigns` | Save target-account context for personalized sessions | The same partner API key |
| Convinced internal MCP, `/mcp/internal` | An approved knowledge analyst integration using Streamable HTTP | OAuth access with the required permissions; partner keys do not authorize this transport |
| Browser WebMCP | Expose actions implemented by your website to the SDK agent | Your website's session and per-action authorization |

For Enmo Buddy or another website integration, start with the [SDK overview](/guides/widget-sdk/overview). Use [WebMCP website tools](/guides/widget-sdk/webmcp) for page actions. WebMCP does not replace the Knowledge REST API or turn a partner key into a browser credential.

<Warning>
  The legacy `GET /sse` and `POST /messages` endpoints are retired and return `410 legacy_transport_retired`. Do not use old Claude Desktop or Cursor snippets that point a partner key at `/sse`.
</Warning>

## Partner Knowledge API

The public service origin is:

```text
https://convinced-kb-mcp-production.up.railway.app
```

A partner key binds each call to its organization. Keep it on your server. The REST request uses the service's tool names, such as `get_product_overview` or `get_customer_story`; these differ from some internal MCP names.

```json
{
  "tool": "search_knowledge",
  "args": { "query": "dispatch planning", "limit": 5 },
  "scope": "partner"
}
```

The stored key scope controls access. Sending another value in the request's `scope` field does not elevate the key. Responses vary by tool: most are JSON, while catalog and proof tools can return Markdown. Read the [tools reference](/guides/mcp/tools) and handle both formats.

## Limits and results

Partner keys default to 2,000 requests per hour per service process, shared with Campaign API requests. The limit is held in memory, so it is not a globally synchronized quota. A REST `429` includes `retryAfterSeconds`. Request bodies are limited to 1 MiB.

A `200` response can contain a tool-level `error`, `noData`, or `action: "skip"`. Treat those as outcomes to handle. Do not turn missing evidence into a factual answer or assume that every tool shares the same response schema.

The partner surface is intended for server-side integration. Review knowledge results before displaying them publicly; access to a knowledge tool does not itself establish that every returned field is approved website content.
