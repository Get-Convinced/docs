Convinced is the authoritative record for identity, conversation history, tools, and lifecycle. PostHog is the observational layer for product events and privacy-masked session replay. Link the two with opaque IDs instead of copying visitor details or transcripts into analytics.

## Initialize PostHog privately

Install PostHog in the host application and keep passive capture off until the visitor has consented:

```ts
posthog.init(import.meta.env.PUBLIC_POSTHOG_KEY, {
  api_host: '/ingest',
  ui_host: 'https://us.posthog.com',
  person_profiles: 'identified_only',
  capture_pageview: false,
  capture_pageleave: false,
  autocapture: false,
  capture_performance: false,
  disable_session_recording: true,
  opt_out_capturing_by_default: true,
  respect_dnt: true,
  session_recording: {
    maskAllInputs: true,
    blockClass: 'ph-no-capture',
    maskTextClass: 'ph-mask',
    recordHeaders: false,
    recordBody: false,
    maskCapturedNetworkRequestFn(request) {
      const url = new URL(request.name, window.location.origin)
      url.search = ''
      url.hash = ''
      return {
        ...request,
        name: url.toString(),
        requestHeaders: undefined,
        responseHeaders: undefined,
        requestBody: undefined,
        responseBody: undefined,
      }
    },
  },
})
```

Proxying `/ingest` through your own origin is optional, but it reduces blocker-related loss and gives you one place to apply a connection allowlist. The PostHog project token is public; a PostHog personal API key is not and must never enter browser code.

## Link PostHog after consent

```ts
import { createPostHogBridge } from '@convinced/widget-sdk'

consentButton.addEventListener('click', async () => {
  posthog.opt_in_capturing()

  const analytics = createPostHogBridge({ client, posthog })
  const link = await analytics.start()

  console.log(link.convincedSessionId)
  console.log(link.posthogSessionId)
  console.log(link.replayUrl)

  await analytics.capture('lab_started', {
    campaignMode: client.state.session?.personalization?.agentMode,
  })
})
```

`start()` registers the Convinced session ID for the PostHog session, starts explicit replay, emits `widget.session_linked`, and writes an `analytics_session_linked` event through the signed Convinced session. The internal session detail page can then open the matching privacy-masked replay.

When `captureIdentity()` succeeds, the bridge calls `posthog.identify()` with the opaque Convinced `visitorId`. It does not send email, name, phone, or company by default. If you opt into person properties with `identityProperties`, apply your own consent, retention, and minimization policy first.

```ts
await client.captureIdentity({
  email: 'priya@acme.example',
  name: 'Priya Rao',
  company: 'Acme',
})

await analytics.capture('proof_slide_opened', {
  slide: 'ai-sales-engineer',
})
```

`analytics.capture()` sends the event to PostHog and the signed Convinced behavior timeline. Pass `{ authoritative: false }` only for a signal that is intentionally PostHog-only.

After `start()`, the bridge also observes the SDK's demo-request lifecycle and sends the hosted-widget taxonomy automatically:

| PostHog event | Safe properties |
| --- | --- |
| `widget.demo_opened` | Form surface |
| `widget.demo_submitted` | Opaque request correlation, timestamp, retry flag, identity-linked flag, and field-presence booleans |
| `widget.demo_failed` | Failure stage, safe error code, and field-presence booleans |

Do not capture these events a second time in the host application. The bridge deliberately omits the submitted name, email, phone, company, and context. When the demo endpoint links identity, PostHog is identified only with the opaque Convinced `visitorId`.

## Separate SDK emission from PostHog ingestion

PostHog's browser `before_send` hook proves that an event passed the SDK's final client-side filter and was offered to the transport. It does not prove that the request reached your proxy, that PostHog accepted it, or that the event is queryable in the project.

Use three distinct acceptance checks:

1. Observe `before_send` only as SDK emission evidence.
2. Require every relevant `/ingest` request to complete successfully.
3. Query PostHog by the opaque `convinced_session_id`, require the expected `widget.demo_opened` and `widget.demo_submitted` events, and assert that email, name, phone, company, form context, and transcript content are absent.

Cross-check the same opaque session in the Convinced dashboard. Do not mark the full analytics path accepted until both the authoritative session record and the PostHog query succeed.

<Warning>
  Browser analytics can be blocked or spoofed. Do not use a PostHog event as proof that identity was captured, a tool was authorized, or a session ended. Read those facts from Convinced.
</Warning>

## Run the real organization lab

The SDK repository includes `examples/real-org-lab`, a localhost-only Acme campaign page backed by the real Convinced dogfood organization. It exercises:

- Private ElevenLabs WebRTC voice with real microphone input, speech recognition, and synthesized audio.
- Campaign identity and personalization.
- SPA navigation, page context, scrolling, and highlighting.
- A bounded MCP-style account-readiness tool.
- A real Convinced slide rendered inside the managed SDK widget.
- Opaque visitor identity, internal session history, and PostHog correlation.
- A real demo-request handoff with identity linkage, durable retry correlation, and consented `widget.demo_*` observation.

Build the SDK, provision the disposable private agent, and start the page:

```bash
cd /path/to/convinced-widget-sdk
bun install
bun run build

cd /path/to/convinced-app/frontend
pnpm exec tsx scripts/e2e-elevenlabs-disposable-agent.ts \
  --source-agent-id=<dogfood-agent-id> \
  --profile=real-org-lab \
  --name='Convinced Widget SDK Real Org Lab' \
  --enable-auth

cd /path/to/convinced-widget-sdk
SAMPLE_ELEVENLABS_AGENT_ID=<disposable-agent-id> \
bun --env-file=../convinced-app/frontend/.env.local run example:real
```

Open `http://localhost:4184/overview?c=acme-robotics`. Grant analytics and page-tool consent, link a test identity, then hold the widget microphone and try:

1. “Take me to security and highlight the controls.”
2. “Show me the AI Sales Engineer proof slide.”
3. “Check the Acme account readiness tool.”

Use **Run demo-request E2E** to create a unique QA request, assert SDK identity, replay the exact same signed request, and require the same `requestId` and `visitorId` with `alreadySubmitted: true`. A changed-identity replay must return `409 demo_request_conflict` and must not change SDK or PostHog identity. The page states explicitly that this is a follow-up request, not a booked calendar time. Its visible result proves durable request correlation and PostHog SDK emission; it does not claim warehouse ingestion. End the session before opening its internal dashboard and PostHog replay links.

## Run the automated microphone acceptance

The acceptance test feeds a WAV file through Chromium's fake microphone. Unlike a text simulation, it waits for real ElevenLabs speech recognition, output audio, every requested browser/MCP tool, identity linking, successful PostHog ingest responses, and final Convinced persistence.

```bash
cd /path/to/convinced-app/frontend

REAL_ORG_LAB_URL='http://localhost:4184/overview?c=acme-robotics' \
REAL_ORG_LAB_AUDIO=/path/to/acceptance.wav \
pnpm exec node scripts/e2e-real-org-widget-sdk-lab.mjs
```

The successful output contains the Convinced session ID, ElevenLabs conversation ID, PostHog session ID, replay URL, completed voice tools, screenshot path, and a return-visitor check. That check renews the client into a second Convinced session and proves the same opaque organization-scoped visitor ID is reused. Use the emitted Convinced session ID for the required PostHog query and internal-dashboard cross-check; do not query by email or another personal field.

## Production acceptance checklist

- The ElevenLabs agent is private and the API key exists only on a backend.
- The backend selects the agent and binds short-lived credentials to the current Convinced session; callers cannot supply an agent ID.
- The active ElevenLabs webhook endpoint and production `ELEVENLABS_WEBHOOK_SECRET` use the exact same provider secret; a current raw-body HMAC is required and unsigned delivery is never enabled in production.
- Convinced production has both `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`. Paid voice fails closed when the atomic shared session, IP, and organization quota cannot be checked.
- The page uses a Content Security Policy and an explicit microphone Permissions Policy.
- Replay begins only after consent, masks every input, blocks sensitive containers, drops network bodies and headers, and removes URL queries and fragments.
- Successful PostHog ingest responses are observed, then the project is queried by opaque `convinced_session_id`; the resulting events contain no raw identity, form context, or transcript content.
- The follow-up demo request appears in the Convinced session with the same opaque visitor and request correlation shown by the sample, while the PostHog query contains `widget.demo_opened` and `widget.demo_submitted` without contact fields.
- Navigation routes, selectors, and MCP tool names use exact allowlists.
- Mutation tools pass both the registry authorization and the handler's live-state authorization.
- A real browser proves microphone input, agent audio, SPA tools, slide/media rendering, identity reuse, successful PostHog ingest plus queryability, and dashboard history before release.
