`ConvincedClient` is the canonical event source for messages, content, tools, identity, and session lifecycle.

```ts
const stopState = client.on('state', state => renderConversation(state))
const stopContent = client.on('content', event => renderContent(event.content))
const stopError = client.on('error', error => showError(error.message))
```

Common client events include:

| Event | Use |
| --- | --- |
| `state` | Render the current state snapshot |
| `message` | Observe completed chat messages; Live-native pairs arrive through state updates instead |
| `message_delta` | Render streaming assistant text |
| `content` | Render structured `text`, `slide`, or `video` parts |
| `client_tool_call` | Show a requested browser action |
| `client_tool_pause` | Diagnose the signed continuation flow |
| `client_tool_result` | Show the observed tool result |
| `identity` | Confirm a durable identity update |
| `error` | Show a recoverable failure |

`paused` means `gpt-6-luna` is waiting for a client tool result. Let the SDK resume it; do not manually submit a duplicate continuation. A deliberate typed correction through `client.sendMessage()` can supersede an unfinished delegated voice turn.

## Live events

```ts
const live = client.createLiveController()

const stopLive = live.on('state', state => renderVoiceState(state))
const stopLiveError = live.on('error', error => showVoiceError(error.message))
```

Live state covers connection, microphone mute, listening, speaking, and errors. Completed Live-native user/assistant pairs are added to `client.state.messages` and notify client state subscribers. They do not emit duplicate client `message` events; use state to render the full shared history.

Live's `onMessage`, `message`, and `message_delta` events still provide captions, including fragments that may not form a completed pair. Do not replay captions as chat requests. Typed and delegated Luna requests can use the completed pairs in shared history. By default, `client.endSession()` includes them in the session-end transcript; it does not capture every partial fragment or guarantee reload/reconnect recovery.

## Typed input during voice

```ts
await client.sendMessage(input.value)
```

This remains the only typed-input path. In SDK 0.1.7, typed input supersedes an unfinished delegated voice task before that task performs another browser action. If Live is connected, the SDK sends the backend's short verified briefing to Live for speech when available, or a bounded complete-sentence fallback. The full client message is unchanged; see [Live payload limits](/guides/widget-sdk/voice#live-payload-limits).

## Pending event handling improvements

Local development forwards verified `voice_context` and `voice_thinking` SSE updates to Live during delegated work. These are bounded backend progress inputs, not new visitor messages or a reason to replay a turn. The published package should not be assumed to include this behavior. Caption buffering and mute acknowledgement fixes are also pending; see [availability](/guides/widget-sdk/overview#availability-and-validation-status).

## Teardown

```ts
stopState()
stopContent()
stopError()
stopLive()
stopLiveError()

await live.end()
await client.endSession()
client.destroy()
```

Use an awaited close path. Browser unload events cannot guarantee durable completion.
