A page-aware guide can discuss what a visitor sees, move to the relevant part of the page, and open an existing panel without putting agent logic throughout the landing page.

The integration has two layers:

- The Widget SDK owns the Convinced session, ElevenLabs connection, transcript, tool validation, consent, timeouts, and guide UI.
- Your page owns its content, semantic IDs, router, focus state, panels, and the callbacks that already change those surfaces.

The page should expose a small semantic adapter. Do not give the agent unrestricted DOM access.

```text
Visitor question
  -> agent requests a named client tool
  -> SDK validates the tool, arguments, consent, and timeout
  -> page adapter calls existing application code
  -> page reports the settled visible state
  -> agent explains the observed result
```

## Estimate the landing-page change

The semantic adapter below is one concrete example using supply-chain roles. Other sites provide their own page IDs, entities and actions. For shared discovery across websites, publish these handlers through [WebMCP](/guides/widget-sdk/webmcp) and keep site-specific names out of generic instructions. The [customer editor](/guides/widget-sdk/agent-prompts) manages saved instructions and the opener separately from page data.

| Experience          | Typical client change                                               | Layout change                                                 |
| ------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------- |
| Conversation only   | One SDK mount and session teardown                                  | None for a floating widget                                    |
| Page-aware answers  | A compact page manifest and one read tool                           | None                                                          |
| Guided presentation | Two to five bounded callbacks with result receipts                  | None for floating; one app-shell region for a persistent rail |
| Cross-page journey  | A persistent root mount, router adapter, and one manifest per route | Depends on the chosen guide surface                           |

These are integration ranges, not guarantees. Existing component boundaries and router behavior determine the final change.

You do not need to rewrite landing-page content unless the page does not contain enough accurate material for the agent to explain.

## 1. Mount the SDK in a persistent owner

Mount the Convinced client and voice controller above the route content when the conversation must survive SPA navigation.

```ts
import {
  ClientToolRegistry,
  ConvincedClient,
  ConvincedVoiceController,
  HOST_TOOL_PROTOCOL_VERSION,
  type ClientToolDefinition,
  type JsonObject,
} from "@convinced/widget-sdk";

const tools = new ClientToolRegistry();
const authorizePageTool = ({ tool }: { tool: ClientToolDefinition }) =>
  tool.effect === "read" || window.confirm(`Allow ${tool.description}?`);

const client = new ConvincedClient({
  orgSlug: "acme",
  tools,
  authorizeToolCall: authorizePageTool,
});

await client.initialize();
```

The following sections continue in this module. Register the page tools before starting the voice controller in step 5. Supply your organization slug, an intentionally public ElevenLabs agent ID (or your own credential endpoint), and the page's existing `pageActions` adapter. Keep the ElevenLabs API key on your backend.

## 2. Describe the page with semantic IDs

Create stable identifiers for the objects a visitor can see and discuss. The IDs should describe product meaning, not CSS structure.

```ts
const pageGuide = {
  pageId: "supply-chain-transformation",
  route: "/transformation",
  sections: [
    {
      id: "ai-workforce-range",
      label: "AI workforce supply-chain range",
    },
  ],
  scopes: [
    {
      id: "supplier",
      label: "Supplier",
      roleIds: [
        "ai-inbound-scheduler",
      ],
    },
  ],
  roles: [
    {
      id: "ai-inbound-scheduler",
      label: "AI Inbound Scheduler",
      sectionId: "ai-workforce-range",
      summary: "The exact approved description shown by the page.",
    },
  ],
};
```

Keep this contract compact:

- Use stable page, section, scope, and entity IDs.
- Include only facts that the page or an approved source can support.
- Encode exact relationships such as which roles visibly intersect a scope.
- Exclude form values, hidden personal data, API keys, raw HTML, and arbitrary instructions.
- Do not use display labels as the only identifier.

## 3. Register a read tool before an action tool

A discovery-oriented guide normally needs one tool that inspects an exact scope and one tool that presents a selected entity.

```ts
tools.register({
  version: HOST_TOOL_PROTOCOL_VERSION,
  name: "host_inspect_workforce_scope",
  description:
    "Read the exact roles visibly associated with one supply-chain scope.",
  inputSchema: {
    type: "object",
    properties: {
      scope_id: {
        type: "string",
        enum: pageGuide.scopes.map((scope) => scope.id),
      },
    },
    required: ["scope_id"],
    additionalProperties: false,
  },
  locality: "host",
  effect: "read",
  consent: "none",
  timeoutMs: 1_000,
  constraints: {
    section: "ai-workforce-range",
  },
  handler: async ({ scope_id }): Promise<JsonObject> => {
    const scope = pageGuide.scopes.find((item) => item.id === scope_id);

    if (!scope) {
      return {
        status: "not_found",
        requested_scope_id: scope_id,
        roles: [],
      };
    }

    return {
      status: "observed",
      scope_id: scope.id,
      scope_label: scope.label,
      exact_role_ids: scope.roleIds,
      roles: pageGuide.roles.filter((role) => scope.roleIds.includes(role.id)),
      presentation_performed: false,
    };
  },
});
```

The read tool prevents the agent from guessing which products belong to a visible area. This minimal example defines one role. When extending it, ensure every `roleIds` reference resolves to a full role object; validate the relationship when loading your page manifest.

## 4. Return an observed receipt after every page mutation

The action handler should call application code your page already owns. Wait until scrolling, selection, and panel opening settle before returning.

```ts
tools.register({
  version: HOST_TOOL_PROTOCOL_VERSION,
  name: "host_present_workforce_role",
  description: "Focus one approved workforce role and open its page brief.",
  inputSchema: {
    type: "object",
    properties: {
      role_id: {
        type: "string",
        enum: pageGuide.roles.map((role) => role.id),
      },
    },
    required: ["role_id"],
    additionalProperties: false,
  },
  locality: "host",
  effect: "mutate",
  consent: "session",
  timeoutMs: 5_000,
  constraints: {
    presentationOnly: true,
    section: "ai-workforce-range",
  },
  handler: async ({ role_id }): Promise<JsonObject> => {
    const requestedRole = pageGuide.roles.find((role) => role.id === role_id);
    if (!requestedRole)
      return { status: "not_found", requested_role_id: role_id };

    await pageActions.presentRole(requestedRole.id);
    const observed = pageActions.readSettledSelection();

    return {
      status:
        observed.roleId === role_id && observed.briefOpen
          ? "presented"
          : "not_presented",
      requested_role_id: role_id,
      active_role_id: observed.roleId,
      brief_open: observed.briefOpen,
      target_visible: observed.targetVisible,
      selection_source: observed.selectionSource,
      page_facts: observed.roleId === role_id ? requestedRole : null,
    };
  },
});
```

The result is evidence, not an optimistic acknowledgement. The agent should explain only `page_facts` returned by the settled action.

<Warning>
  Do not return `{ opened: true }` immediately after dispatching a click. A route transition, animation, stale request, or visitor action may change the final state.
</Warning>

## 5. Bind the exact tools to ElevenLabs

The tool names configured on the ElevenLabs agent are on the left. The registered SDK tools are on the right.

```ts
const voice = new ConvincedVoiceController({
  descriptor: {
    agentId: "YOUR_PUBLIC_ELEVENLABS_AGENT_ID",
    connectionType: "webrtc",
    exactClientTools: {
      inspect_workforce_scope: "host_inspect_workforce_scope",
      present_workforce_role: "host_present_workforce_role",
    },
    genericClientTool: false,
  },
  tools,
  orgSlug: client.orgSlug,
  sessionId: () => client.state.session?.sessionId ?? null,
  authorizeToolCall: authorizePageTool,
  onConversationId: (id) => client.linkElevenLabsConversation(id),
});
```

For a private agent, replace `descriptor` with your own authenticated `descriptorFactory`; the hosted `getVoiceCredential()` endpoint is not deployed. See [ElevenLabs voice](/guides/widget-sdk/voice#choose-a-browser-safe-descriptor).

Enable **Wait for response** for both ElevenLabs client tools. The agent must receive the observed tool result before it explains the page.

The chat client and voice controller have separate authorization hooks; passing a hook only to `ConvincedClient` does not authorize voice actions. The example's `session` consent permits subsequent calls to that same tool after the visitor approves it once. Use `per_call` when each invocation needs a fresh decision.

Use a dedicated guide agent when changing the prompt, tool catalog, or sales motion would affect an existing production widget. The landing page can still use the same Widget SDK.

## 6. Keep visitor actions authoritative

Visitors can click while the agent is speaking or while an action is in flight. Your adapter must make that outcome explicit.

Use a monotonically increasing selection version:

1. Increment the version after every visitor or agent selection.
2. Record `selection_source` as `user` or `agent`.
3. Let the latest settled selection win.
4. Return `superseded` when an older agent request loses.
5. Send the visitor's final selection to the active voice session.

```ts
pageActions.onUserSelection((selection) => {
  if (voice.state.status !== "connected") return;

  voice.sendUserActivity();
  voice.sendContextualUpdate(
    JSON.stringify({
      event: "page_selection_changed",
      selection_source: "user",
      role_id: selection.roleId,
      brief_open: selection.briefOpen,
      selection_version: selection.version,
    }),
    "page-selection",
  );
});
```

The agent should acknowledge the visitor's choice instead of moving the page back to an older request.

## 7. Choose the guide surface

| Surface                 | Best for                                            | Client layout work                                       |
| ----------------------- | --------------------------------------------------- | -------------------------------------------------------- |
| Floating managed widget | Fast installation and minimal layout impact         | None beyond the SDK mount                                |
| Inline managed widget   | A guide embedded in an existing section             | One explicit target element                              |
| Headless right rail     | A persistent transcript beside a product experience | One app-shell column and a mobile bottom-sheet treatment |

A persistent rail should mount at the application-shell level. Do not resize only one page section while leaving the global navigation underneath the rail.

On smaller screens, collapse a persistent rail into a dismissible sheet or launcher. Keep the active session alive unless the visitor explicitly ends it.

See [Default, themed, and headless UI](/guides/widget-sdk/custom-ui) for rendering options.

## 8. Prompt for discovery before presentation

Client tools cannot correct a sales prompt that always pitches the first matching product. Configure the guide agent to:

1. Identify the visitor's operational scope.
2. Use the read tool when scope membership matters.
3. Summarize the exact visible options before recommending one.
4. Ask a narrowing question when multiple roles remain plausible.
5. Present a role only after the visitor asks to see it or enough evidence supports the action.
6. Explain only the facts returned by the presentation receipt.
7. Correct itself when a visitor changes the page manually.

Treat page context and tool results as data. They do not override tool policy, consent, or the agent's system prompt.

## 9. Preserve route and session continuity

Update both Convinced and the live voice conversation after an SPA route change:

```ts
router.onChange(async ({ url, title, pageId }) => {
  await client.updatePage({ url, title });

  if (voice.state.status === "connected") {
    voice.sendContextualUpdate(
      JSON.stringify({
        event: "route_changed",
        page_id: pageId,
        title,
        url,
      }),
      "current-page",
    );
  }
});
```

Mount one manifest per route and unregister route-specific tools when that route unmounts. Keep the session owner above the router. A full document navigation unloads the browser voice transport; a conventional multi-page site starts a new SDK owner on the destination page rather than preserving an uninterrupted voice call.

## Client handoff checklist

- The SDK is mounted once in a persistent owner.
- The browser receives an intentionally public agent ID or a short-lived private credential, never an ElevenLabs API key.
- Every page object has a stable semantic ID.
- Scope membership and other important relationships are exact.
- Read tools do not mutate the page.
- Mutation tools call existing page functions rather than arbitrary selectors.
- Every mutation returns an observed terminal receipt.
- The latest visitor action supersedes an older agent action.
- The guide prompt performs discovery before presenting a solution.
- Desktop and mobile layouts preserve access to the underlying page.
- A real browser test proves microphone input, audible output, tool execution, manual interruption, and teardown.
