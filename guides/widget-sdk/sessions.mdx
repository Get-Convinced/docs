`client.initialize()` creates one Convinced session for a live `AgentDeployment`. Typed input and grounded delegated work use its `gpt-6-luna` conversation. Optional Live voice can answer greetings and conversational clarifications directly.

## Session rules

- Mount one client for one visitor conversation.
- Reuse it across SPA route changes.
- Attach and detach optional Live voice from that client.
- Use one shared `ClientToolRegistry` for the session.
- End the session explicitly when the visitor finishes.

Starting voice attaches a Live transport to the same Convinced session. Luna remains responsible for grounded organization, page, slide, and tool requests. Completed Live-native user/assistant pairs join the shared client history, which supplies context to typed and delegated Luna requests. A Live session ID identifies the transport, not a new host-owned conversation.

## Update page context

```ts
router.onChange(({ url, title }) => {
  client.updatePage({ url, title })
})
```

Keep page context compact and free of form values, secrets, raw HTML, or arbitrary instructions.

## Renew after completion

```ts
await client.endSession()

// If the visitor starts a new conversation later:
await client.renewSession()
```

Do not send new turns into a completed session. Session renewal preserves permitted attribution and browser continuity while creating a new canonical conversation.

## Persisted history

`client.state.messages` includes Luna turns and completed Live-native user/assistant pairs, within the SDK's text and history limits. Native pairs notify state subscribers without duplicate client `message` events. Live's `onMessage` and transcript events can still drive captions; do not replay them as new chat requests or merge them into history at teardown.

By default, `await client.endSession()` sends the completed pairs with the session transcript to `/session/end`. If you supply `clientMessages` explicitly, that replaces the default transcript; preserve the messages you intend to submit. Session-end capture covers completed pairs rather than every partial speech fragment. It does not establish reload or reconnect recovery.

See [Lifecycle events](/guides/widget-sdk/events) for observable state and [Security](/guides/widget-sdk/security) for session capabilities.
