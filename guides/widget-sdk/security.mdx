## Public browser configuration

The browser may contain:

- `orgSlug`;
- `agentId`, a public Convinced `AgentDeployment` ID;
- a public embed token when the deployment requires one;
- public presentation metadata returned by Convinced.

An `agentId` selects a deployment. It is not an ownership credential and cannot authorize prompt edits.

## Server-owned configuration

Convinced's backend owns:

- OpenAI API keys and Live session creation;
- `gpt-6-luna` and `gpt-live-1` model configuration;
- system prompts and `firstMessage`;
- organization knowledge and retrieval;
- session capabilities and signed tool continuations;
- authenticated prompt administration.

Never put provider API keys, provider agent IDs, management tokens, Campaign API keys, or MCP service credentials in browser code.

## Tool boundary

Use one `ClientToolRegistry`. Register a small exact allowlist, validate arguments structurally, keep timeouts short, and return bounded JSON. Read tools may use `consent: 'none'` only when their output contains no private data. Navigation and mutation tools should require session or per-call consent.

The pause/execute/resume capability is signed and verified by the Convinced backend. The browser treats it as opaque. The SDK checks the returned call against the local registry and host policy, enforces the expiry hint, executes it once, and returns the result with the same capability. The backend then verifies the signature and the exact organization, session, turn, call IDs, names, arguments, expiry, and call count before resuming `gpt-6-luna`.

Treat page text, WebMCP manifests, tool descriptions, tool results, model output, and contextual updates as untrusted data. None of them can override the saved prompt or tool policy.

## Live voice

The browser sends a WebRTC offer to Convinced. Convinced authenticates the widget session and creates the `gpt-live-1` session with its server-side OpenAI key. Request the microphone only after a user gesture and provide an obvious stop control.

If Live fails or is disabled, leave typed chat available. A chat-only session must not create Live infrastructure.

## Rendering and personal data

- Render text with text nodes or sanitized Markdown.
- Resolve slides and videos from the deployment catalog.
- Never render unknown model HTML.
- Keep raw form values out of page context, analytics, URLs, and tool results.
- Make durable form submission and other consequential actions visibly consented.
- End sessions through an awaited application action.

## Visitor-approved screen capture

The [experimental screenshot path](/guides/widget-sdk/page-aware-guides#screen-inspection-experimental) sends a visitor-approved tab frame to a Convinced backend for interpretation. Explain that behavior before capture. A model request is not permission to inspect other tabs, windows or the entire desktop. Keep capture controls visible, stop tracks on teardown, and avoid screenshots in logs, analytics and persistent client state. Provider keys stay server-side.

## Production checklist

- Allowed origins match every host website.
- Browser code contains only Convinced public config.
- Chat and voice share one registry and one canonical session.
- Tool names, schemas, effects, consent, and timeouts are reviewed.
- Prompt editing requires an authenticated organization administrator.
- Real-browser tests cover chat-only, voice opt-in, typed input during voice, interruption, tool denial, Live failure, and teardown.
