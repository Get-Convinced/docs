Use the [SDK overview](/guides/widget-sdk/overview) to choose a headless or managed UI, then follow the [quickstart](/guides/widget-sdk/quickstart). Keep customer-specific deployment IDs, prompts, repository links and acceptance evidence in that customer's implementation handoff.

## Release status

The published npm version is **0.1.7**. Local streaming, screenshot and transcript/mute fixes are not a new published release. The [availability table](/guides/widget-sdk/overview#availability-and-validation-status) distinguishes those changes. Voice rollout remains blocked by the unresolved false-input report; working chat and passing automated tests do not establish acoustic acceptance.

## Configuration to supply

- The customer's `orgSlug` and public Convinced `agentId`, plus permitted website origins.
- The exact package pin and lockfile, backend environment and required hosted capabilities.
- The chosen renderer and implemented page, form and media tools.
- Who can administer `systemPrompt` and `firstMessage`, through authenticated Convinced administration.
- Verified browser behavior, known limitations and rollback steps.

The browser needs no provider key or provider agent ID. Reuse a Convinced deployment ID only when the new page should share its prompt and configuration; otherwise provision a separate deployment. Register capabilities that actually exist on each page rather than copying another page's tool names without handlers.

## Preserve product capabilities

Identity capture, session persistence, forms, slides and WebMCP remain supported. A headless host must wire its form UI to the [identity APIs](/guides/widget-sdk/identity); forms do not appear automatically. A page can instead use [page-owned visual tools](/guides/widget-sdk/page-aware-guides) without removing SDK slides from other integrations.

Experimental snapshots require a matching unpublished SDK/backend pair and a visitor-controlled tab-sharing action. Do not promise screenshot support from the released package.

## Acceptance and rollout

Use [Analytics and testing](/guides/widget-sdk/analytics-and-testing) for chat, identity, tools, media, silence, mute, interruption and teardown checks. Record exactly what passed, failed or was not tested. Keep a local preview URL distinct from production and start a fresh session after a runtime change.

Use the [migration guide](/guides/widget-sdk/migration) for existing integrations, [prompt guide](/guides/widget-sdk/agent-prompts) for saved prompt edits, and [WebMCP study links](/guides/widget-sdk/webmcp#official-study-links) for browser-tool implementation.
