SDK 0.1.2 gives website teams a headless chat and voice client. The website owns its interface, slides, forms, and page actions. Convinced owns the prompt, knowledge, models, session, and provider credentials.

## What changed in 0.1.2

- Text and spoken turns share one `gpt-6-luna` conversation and its knowledge and tool decisions. Optional `gpt-live-1` adds full-duplex speech through WebRTC and client delegation; voice can stop while chat continues.
- The browser uses the public Convinced `agentId` to select a deployment. It receives no OpenAI key or provider agent ID.
- One `ClientToolRegistry` powers slides, forms, page actions, and WebMCP for both input modes. `client.publishToolsToWebMcp()` exposes that registry to supporting browsers.
- Browser tool calls pause and resume through a short-lived signed capability. Convinced checks the session and exact calls, and accepts each continuation once.
- An authenticated Convinced administrator can edit the deployment's saved `systemPrompt` and `firstMessage` with `ConvincedAgentAdmin`. The changes apply to future sessions.

## Enmovil ID for new pages

The **Enmo Buddy SDK** deployment uses:

```ts
const client = new ConvincedClient({
  orgSlug: 'enmovil',
  agentId: 'c4b50540-3323-4037-a2e5-6807d0f1be17',
  tools,
})
```

Use this ID when duplicating the Transformation page's prompt and behavior on another Enmovil page. A different prompt should have its own Convinced deployment and ID. The generic **Test Widget** ID is not the Transformation agent. Add each new website origin to the deployment's allowed domains before testing it.

Pin `@convinced/widget-sdk@0.1.2`, build the host UI, and register only the slide, form, navigation, and WebMCP actions that the page can really perform. Test chat only, voice opt-in, voice with slides, typed input during voice, tool approval and denial, and explicit session completion in the deployed page.
