This example adds the supplied `managed-v2` interface to an existing browser application. It creates a Convinced session, connects a public ElevenLabs agent when the visitor starts voice, and exposes page context, scrolling and highlighting. Campaign attribution is optional.

<Note>
  This quickstart uses the supplied `managed-v2` widget. If your application needs to own the interface, use [Custom UI and headless](/guides/widget-sdk/custom-ui#when-to-use-headless).
</Note>

## 1. Install

Use Node.js 22.14 or newer. From your application's package directory:

```bash
npm install --save-exact @convinced/widget-sdk@0.1.1-webmcp.2
```

Commit the lockfile. Load the code below through your application's bundler on the client, after the DOM exists. For a script-tag integration, see [browser bundle](/guides/widget-sdk/migration).

## 2. Configure your organization and agent

You need your provisioned Convinced `orgSlug`, the website's allowed origin and a public ElevenLabs `agentId`. Supply `widgetToken` if your deployment requires it. Use HTTPS or localhost for microphone access.

Download the [ElevenLabs managed tool definitions](/examples/elevenlabs-managed-tools.json). Each entry contains a `tool_config` with the exact name, description, input schema and response setting. Configure matching client tools in the ElevenLabs dashboard or through its [Tools API](https://elevenlabs.io/docs/api-reference/tools/create), then attach their tool IDs to your agent.

For this quickstart, attach these **nine** client tools:

| Tools | Supplied by |
| --- | --- |
| `show_slide`, `show_youtube_embed` | Managed renderer; content must exist in the session's allowed catalog |
| `set_visitor_field`, `request_email_capture`, `confirm_visitor_form` | Managed identity interface; submission needs host authorization |
| `show_book_demo_cta` | Managed renderer using deployment settings |
| `host_get_page_context`, `host_scroll_to`, `host_highlight` | This example's DOM tool registry |

The download also includes optional `host_navigate` and `host_extension_call`. This quickstart does not activate them. Add them only with matching handlers and bindings. Use **Wait for response** so the model can inspect each result before claiming success.

Enable the agent's first-message conversation override. The managed widget supplies its selected greeting, including configured, campaign and return-visitor greetings, as a voice-start override. A saved opener and a session override have different scopes; see [prompts and first message](/guides/widget-sdk/agent-prompts).

<Note>
  This example uses a public agent. For private agents, implement a server-issued descriptor as described in [ElevenLabs voice](/guides/widget-sdk/voice). The published `client.getVoiceCredential()` helper targets an undeployed hosted endpoint and returns `404`.
</Note>

## 3. Add the browser module

Save the [complete typed module](https://raw.githubusercontent.com/Get-Convinced/docs/9b40f1192b70035d7577f38ae2313487b75db166/examples/sdk-quickstart.ts) as `sdk-quickstart.ts` in your application. It defines the registry, permissions, session, voice controller, managed widget and cleanup in one function.

Call it from your browser entry point:

```ts
import { createWebsiteWidget } from './sdk-quickstart'

async function main() {
  const integration = await createWebsiteWidget({
    orgSlug: 'YOUR_ORG_SLUG',
    publicAgentId: 'YOUR_PUBLIC_ELEVENLABS_AGENT_ID',
    // widgetToken: 'YOUR_PUBLIC_WIDGET_TOKEN', // If required
  })

  // Keep this owner for the lifetime of your application.
  // Call await integration.dispose() when the application deliberately ends it.
  return integration
}

main().catch((error) => {
  console.error('Widget initialization failed', error)
  const message = document.createElement('p')
  message.textContent = 'The assistant could not start. Please try again later.'
  document.body.append(message)
})
```

Replace both placeholders before running. The SDK defaults to `https://app.getconvinced.ai`; this example does not require a campaign token, private application checkout, or browser-side ElevenLabs API key.

The module passes authorization to both chat and voice and separately approves DOM mutations. Its confirmation dialogs are a minimal example; replace them with your application's policy and consent UI. Browser-side authorization does not replace server access checks.

## 4. Run and verify

Start your application's development server. Expect a **Talk to us** launcher with the managed voice and chat interface.

1. Open it and confirm configuration and session initialization succeed.
2. Press the voice control and grant microphone access. Deployment settings may require an identity step or chat warmup first.
3. Confirm the intended agent speaks. Ask it to describe the page, then highlight a visible heading. Approve the action and verify the page changed.
4. Deny an action and confirm the agent reports the denial.
5. Try chat and confirm a text reply. The hosted chat route does not implement the complete client-tool continuation protocol; this does not prove chat-driven page actions.
6. End the session and verify the request succeeds. Check stored history separately if that is part of your launch requirements.

The widget registers managed voice callbacks when `widget.startVoice()` or its voice control starts the conversation. Calling `voice.start()` directly does not install the renderer's managed callbacks.

## 5. Extend the integration

- **More pages:** Keep one owner mounted and update route context. Add navigation through your router using [host tools](/guides/widget-sdk/host-tools).
- **Dynamic website tools:** Follow [WebMCP](/guides/widget-sdk/webmcp) for two discovery/execution callbacks. A headless WebMCP agent and the managed renderer use different callback sets.
- **Your own interface:** Reuse the clients with [custom UI](/guides/widget-sdk/custom-ui).
- **Saved instructions and opener:** Build an authenticated [agent editor](/guides/widget-sdk/agent-prompts).

Use the [implementation checklist](/guides/widget-sdk/client-handoff) to verify your website and real voice flow before launch.
