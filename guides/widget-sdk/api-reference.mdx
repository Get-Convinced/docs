Import public APIs from `@convinced/widget-sdk@0.1.1-webmcp.3` using the module name `@convinced/widget-sdk`. The installed package's TypeScript declarations are the exact signature reference; this page groups them by the work they perform.

## Session and chat

`ConvincedClient({ orgSlug, apiBase?, widgetToken?, tools?, fetch?, authorizeToolCall?, ... })` owns widget session and chat state.

| Operation | Methods |
| --- | --- |
| Initialize and read configuration | `initialize()`, `getConfig()`, `createSession()`, `renewSession()`, `state` |
| Converse | `sendMessage()`, `cancelActiveTurn()` |
| Identity and enrichment | `captureIdentity()`, `identify()`, `setIdentity()`, `getVisitorIntel()` |
| Voice ownership | `createVoiceController()` |
| Low-level voice association | `getVoiceCredential()` (hosted endpoint unavailable), `markVoiceUpgrade()`, `linkElevenLabsConversation()` |
| Media | `getSlides()`, `getSlideMetadata()` |
| Site and session context | `updatePage()`, `updateSessionContext()` |
| Lifecycle events | `track()`, `sendEvent()`, `on()`, `once()`, `off()` |
| Application tools | `registerTool()`, `tools` |
| Lead handoff | `reportDemoRequestOpened()`, `submitDemoRequest()` |
| Teardown | `endSession()`, `destroy()` |

The hosted service currently lacks the private `voice-token` endpoint and the complete signed chat-tool continuation protocol. Package methods describe the SDK interface, not backend availability. See [current availability](/guides/widget-sdk/overview#current-availability).

Use `browserSessionInput()` and `resolveWidgetSessionAttribution()` to prepare attribution. `forgetBrowserVisitorKey()` clears the SDK continuity key for privacy controls. See [campaigns](/guides/widget-sdk/campaigns), [identity](/guides/widget-sdk/identity) and [events](/guides/widget-sdk/events).

## ElevenLabs conversation

`ConvincedVoiceController` accepts either a browser-safe `descriptor` or a fresh `descriptorFactory`, plus tools and optional session linkage.

| Operation | Methods or fields |
| --- | --- |
| Connect or end | `start(context?)`, `end()` |
| Observe | `state`, `subscribe()`, `on()`, `once()`, `off()` |
| Input and context | `sendUserMessage()`, `sendContextualUpdate()`, `sendUserActivity()` |
| Audio | `setMuted()`, `setVolume()`, `startPushToTalk()`, `stopPushToTalk()` |
| Voice tool contract | Descriptor `exactClientTools` and `genericClientTool` |

`buildManagedVoiceStartContext()` assembles the managed session, campaign and page context for a headless start. `buildVoiceOutreachContext()` prepares outreach data. These are conversation inputs; they do not persist agent settings. See [voice](/guides/widget-sdk/voice).

## Saved agent configuration

Available in `0.1.1-webmcp.3` with the deployed authenticated management API. This example shows the call shape; supply your organization, agent ID and management origin:

```ts
const admin = new ConvincedAgentAdmin({ orgSlug, agentId, apiBase })
const current = await admin.getPrompt()
const saved = await admin.updatePrompt({
  systemPrompt: 'Your agent instructions',
  firstMessage: 'Your opening message',
  expectedRevision: current.revision,
})
```

Both methods return `AgentPrompt`. `UpdateAgentPromptInput` accepts either field or both, with `expectedRevision` required. Use this only through authenticated management access. See [prompts and first message](/guides/widget-sdk/agent-prompts).

## Tool adapters

| API | Role |
| --- | --- |
| `ClientToolRegistry` | Register, list, validate and execute explicit client tools |
| `createDomTools()` / `registerDomTools()` | Opt-in page context, SPA navigation, scrolling and highlighting |
| `createMcpTools()` | Adapt tools from an already-connected caller-owned MCP client |
| `getWebMcpModelContext()` | Detect the optional browser model context |
| `publishRegistryToWebMcp()` | Publish existing registry handlers; returns `ready` and `dispose()` |
| `createWebMcpBridge()` | Discover browser tools; returns two registry tools plus `listTools()`, `executeTool()` and `dispose()` |
| `WEBMCP_VOICE_BINDINGS` | The two fixed ElevenLabs-to-SDK callback mappings |

The WebMCP helpers require the prerelease and a compatible browser implementation. Ordinary registry limits remain in place; the bridge uses two entries to access a discovered catalog. See [host tools](/guides/widget-sdk/host-tools) and [WebMCP](/guides/widget-sdk/webmcp).

## Rendering and analytics

- `mountConvincedWidget()` returns the mounted UI owner, including `open()`, `close()`, `startVoice()`, `endVoice()`, `endSession()`, `destroy()` and `host`.
- `parseAssistantContent()`, `stripAssistantDirectives()` and `toSafeVideoEmbedUrl()` support safe custom media rendering.
- `createPostHogBridge()` / `ConvincedPostHogBridge` correlate consented analytics with SDK sessions.
- `ConvincedApiError` carries HTTP status, API code and response details; `ConvincedSdkError` represents SDK-level failures.

The mounted renderer owns its transcript/media bookkeeping. Headless controllers created through the client capture turns automatically; the renderer supplies shown slide filenames when used.

## Session ownership API

SDK `0.1.1-webmcp.3` adds `client.createVoiceController(options?)`. It returns a `ConvincedVoiceController` attached to that client and exports `SessionVoiceOptions`. These options omit caller-owned `orgSlug` and `sessionId`, accept an optional tool registry, exact mappings and generic gateway setting, and retain descriptor/descriptor-factory and UI callbacks.

Use `client.endSession()` to stop attached voice and submit the captured mixed transcript. Provider IDs are internal to this flow. The matching backend is required. See [migration, limits and release requirements](/guides/widget-sdk/events#session-owned-headless-voice).
