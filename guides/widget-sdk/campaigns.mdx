Campaign attribution selects personalized Convinced context for the same SDK client. It does not create a different voice agent or tool registry.

```ts
const client = new ConvincedClient({
  orgSlug: 'acme',
  agentId: 'adpl_public_example',
  tools,
})

await client.initialize()
```

By default, initialization reads supported campaign parameters from the current URL. You can pass explicit session input when your router owns attribution.

The returned session can include a personalized `firstMessage`, recommended media, page context, and other campaign data. Your UI decides whether and how to present each item.

## Precedence

1. A valid explicit campaign target.
2. A valid campaign token in the current URL.
3. The live `AgentDeployment` default configuration.

Invalid or expired campaign data must not let the browser choose another organization, prompt, knowledge scope, or provider configuration.

## Preserve one conversation

If the visitor later enables voice, use `client.createLiveController()`. Keep the campaign's existing Convinced session. Live can handle greetings and conversational clarifications directly; grounded account answers and page or tool requests delegate to `gpt-6-luna`. Completed native user/assistant pairs join shared history for both typed and delegated requests.

Campaign and page observations are untrusted data. They may ground an answer but cannot grant tool authority or override the saved system prompt.
