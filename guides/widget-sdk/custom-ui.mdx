The 0.1.7 SDK core is headless. A headless host renders every visible surface and decides how those surfaces behave on desktop, mobile, and embedded pages. If a functional default is enough, use the optional `mountConvincedWidget({ client, voice: live })` renderer instead.

## Render from state

```ts
const unsubscribe = client.on('state', state => {
  renderMessages(state.messages)
  renderTurnStatus(state.status)
})

form.addEventListener('submit', async event => {
  event.preventDefault()
  const text = input.value.trim()
  if (!text) return
  input.value = ''
  await client.sendMessage(text)
})
```

Use either full state snapshots or granular events for a given visual region. Mixing both for the same message list can duplicate content.
Keep the composer available while a delegated voice task streams or waits for a browser tool. The visitor can type a correction; the SDK supersedes unfinished delegated work before its next browser action. For other concurrent typed turns, the SDK serializes requests.

Treat suggested-question chips as shortcuts for the same `client.sendMessage()` path as the composer. A chip should add one user turn to the canonical conversation, not advance a separate page-defined agent journey. Keep actual UI commands, consent, and form validation in the host with observable results.

## Own presentation behavior

Your UI decides:

- where the conversation opens and how it closes;
- colors, typography, spacing, motion, and accessibility;
- whether voice is exposed and which controls are visible;
- how slides, videos, links, and tool receipts appear;
- how identity and other forms collect consent;
- what happens when a tool, network request, or microphone fails.

The SDK emits structured content. A slide event identifies approved media; it does not dictate a carousel, modal, side rail, or transition.

```ts
client.on('content', ({ content }) => {
  for (const part of content) {
    if (part.type === 'text') appendText(part.text)
    if (part.type === 'slide') showSlide(part)
    if (part.type === 'video') showVideo(part)
  }
})
```

The content union is `text | slide | video`. Forms are host UI opened or updated by registered tools; they are not message content parts. Render model text as text or through a sanitized Markdown pipeline. Treat unknown directives as inert text. Render only media resolved from the initialized deployment catalog.

## Keep voice attached to the same client

```ts
const live = client.createLiveController()

live.on('state', state => {
  micButton.dataset.status = state.status
  micButton.setAttribute('aria-pressed', String(state.status === 'connected'))
})
```

Render the shared conversation from `client.state.messages`, which includes Luna turns and completed Live-native user/assistant pairs. Native pairs notify client state subscribers without duplicate client `message` events, so a renderer that only appends `message` events will miss them. Live's `onMessage`, `message`, and `message_delta` events remain available for captions; do not replay them through `client.sendMessage()`. Ending Live leaves chat active. See [session-end capture](/guides/widget-sdk/sessions#persisted-history) for completed pairs and transcript limits.

## Framework lifecycle

Create one `ConvincedClient` above the portion of an SPA that changes routes. Unsubscribe component listeners on unmount. Call `client.updatePage()` when route context changes, and end the session only when the user finishes the conversation.

See [Slides and media](/guides/widget-sdk/media), [Identity](/guides/widget-sdk/identity), and [Lifecycle events](/guides/widget-sdk/events) for the structured state your renderer can consume.
